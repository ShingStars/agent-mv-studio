# 案例研究：从两支参考片到两套语法

> 本仓库不是对某一支 MV 的临摹，而是对**两种可复现语法**的工程化。
> 这份文档记录：看了什么、提炼了什么、放弃了什么、为什么。

---

## 1. 参考对象

### A. *world.execute(me)* 歌词影像（Nyankomintsu）

- 媒介：浏览器 Canvas2D + WebGL2，逐帧导出，无剪辑软件；
- 时长：约 212 秒（含 5 秒静默片头），130 BPM，87 个镜头，平均 2.49 秒/镜；
- 结构：**界面 / 版画 / 代码**三种画面；
- 颜色：橙（我）/ 米白（你）/ 红（错误）/ 灰（缺席）/ 黑（系统）；
- 角色：无脸剪影（胸像、侧脸、伸出的手、眼睛、猫）；
- 时间：所有切点落在拍/半拍/小节；关键时间由音频分析测量，集中在 `cues.js`；
- 交付：4K60、BT.709、逐帧可复现；
- 资产与歌：代码 MIT，剪影 CC BY-NC-SA，歌曲与歌词不随仓库分发。

### B. *world.search(you)* DSH PV（MisakaZentai）

- 媒介：Python/Pillow 画左侧终端 + Playwright 截取静态页面到右侧聊天窗，FFmpeg 合成；
- 时长：约 305 秒（含片尾），1280×720 24fps，7315 帧；
- 结构：**终端（搜索）/ 聊天窗（人格）/ 内部结构图（解码）/ 页面（事实）**；
- 颜色：米白纸 + 深色终端 + 蓝色人格；
- 时间：词级时间 + 拍网格；静态页面按歌曲时间锁 CSS 动画后截图；
- 工程：`page_recipes.json` 固定每帧的页面状态；`data/pages/*.json.xz` 保存上传版本的逐帧 HTML；
- 资产与歌：代码 MIT，美术 CC BY-NC-SA，歌/歌词/字体/成片不分发。

两支片的共同点，比差异更重要：

1. 画面是时间的函数，不是时间线上的关键帧；
2. 颜色有语义，不是配色方案；
3. 窗口/界面不是"背景"，是角色生活的空间；
4. 高潮靠**排版与错位**，不靠特效堆叠；
5. 最后都有一个"干净、静止"的收束镜头。

## 2. 提炼：哪些是语法，哪些是素材

| 层 | 可迁移（写进本仓库） | 不可迁移（不复制） |
|---|---|---|
| 时间 | 拍网格、词时间、preroll、逐帧确定性 | 具体秒数、具体 BPM |
| 画面 | 三种画面轮换、三色油墨、字体角色、层数 | 具体剪影、构图、角色设计 |
| 叙事 | 窗口作为世界、系统作为第三方声音 | 具体歌词、故事、角色名 |
| 工程 | 浏览器渲染 + FFmpeg 收流、静帧验收、闪光预算 | 原仓库代码、页面快照、字体子集 |
| 资产 | 生图规格（透明、单色、无五官） | 原片美术、艺人形象 |

结论：**复现语法，不复制素材；复现约束，不复制画面。**

## 4. 数字对比

| 指标 | 参考 A | 参考 B | 本仓库 Plate | 本仓库 TUI |
|---|---|---|---|---|
| 时长 | 212 s | 305 s | 29.39 s | 29.39 s |
| 分辨率 | 4K60 | 720p24 | 1080p30 | 720p24 |
| 镜头数 | 87 | — | 11 | 11 |
| 平均镜长 | 2.49 s | — | 2.67 s | 2.67 s |
| 渲染方式 | 浏览器逐帧 | Pillow + 截图 | 浏览器逐帧 | 浏览器逐帧 |
| 素材依赖 | 剪影 PNG | 页面快照 | 2 张剪影 | 0 张位图 |
| 代码量 | 大 | 大 | 小（可读、可改） | 小 |

本仓库刻意做小：**用 11 个镜头证明语法，而不是用 87 个镜头证明产能。**
新项目可以在这个骨架上扩到 80+ 镜，成本主要在分镜与资产，不在引擎。

## 5. 放弃的东西（以及为什么）

1. **不复制原片的剪影/构图/字体子集。** 版权与风格独立性都不允许。
2. **不做逐帧 HTML 截图。** 参考 B 的快照方案能 1:1 复现上传版本，但不可维护；
   本仓库选择"代码即状态"，换机器也一致。
3. **不做强制对齐（forced alignment）。** 需要额外的声学模型与歌词文本；
   当前用 LRC 词标签 + 音节估算，足够做 MV，不够做卡拉 OK 字幕。
4. **不做 4K 首版。** 先保证 1080p 的语法正确；4K 只是改输出尺寸与渲染时间。
5. **不做通用 NLE。** 没有拖拽时间线、没有关键帧编辑器；改片子就是改 YAML/代码。

## 6. 经验

### 6.1 时间必须被"编译"

参考 A 的所有"约"时间最后都收敛到一个 `cues.js`，每条带来源标记。
这是它能在 87 个镜头里保持同步的根本原因。本仓库把这个做法制度化：
`project.yaml` 只允许网格/行/词引用，编译后写进 `plan.json` 与 `STORYBOARD.md`。

### 6.2 风格靠"禁止"定义

三色、无五官、一镜一事、红色不提前——这些"不许"比"要好看"更能约束 Agent。
`STYLE_*.md` 里每条规则都写成可检查的句子，评审时逐条打勾。

### 6.3 验收必须比生成便宜

生成一帧要几秒，验收一帧只要看一眼。
所以流水线把预算花在**接触表、strip、静帧**上，而不是"整片重渲染再看"。

### 6.4 让"最后一眼"干净

两支参考片都在结尾回到干净、静止、明亮的画面。
这不是审美偏好，是叙事收束：观众需要一个可以停留的帧。

## 7. 可复现性记录

- Plate demo：`examples/plate-demo/`（含 `project.yaml`、`lyrics.lrc`、`analysis.json`、`plan.json`、`STORYBOARD.md`、`assets/figures/*.png`）。
