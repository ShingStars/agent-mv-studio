# 方法论：把 MV 写成程序

> 这份文档回答一个问题：**为什么"逐帧函数"比"剪辑软件 + 素材堆叠"更适合 Agent，以及怎么把它做好。**

---

## 1. 核心命题：MV = f(t)

一支 MV 可以被描述成一个函数：

```
frame(t) = 场景(镜头表(t), 歌曲状态(t), 调色板状态(t), 素材, 随机种子)
```

其中 `t` 是歌曲时间（秒），不是帧号。这个选择带来四个直接后果：

1. **可重入**：任何一帧都能独立渲染，不需要"从头播一遍"。
2. **可并行**：帧之间无依赖，渲染可以分块、可以重跑某一段。
3. **可验收**：任意 `t` 都能出静帧，错误能被定位到具体的镜头与秒。
4. **可复现**：没有"上次拖到哪"的隐性状态；随机数由 `(seed, shot, frame)` 决定。

反面做法是"时间线状态机"：场景记住上一帧的位置、粒子的速度、镜头的推拉进度。
一旦中途跳帧或换机器，状态就分叉，Agent 无法判断自己看到的是不是同一支片。

**规则：场景函数里不允许出现 `Date.now()`、`Math.random()`、跨帧变量。**
需要随机就用 `frameRng(seed, shotId, frame)`；需要运动就用时间的闭式函数（`ease(t)`、`sin(ωt)`），
而不是"每帧加一点"。

## 2. 时间的三层结构

| 层 | 单位 | 来源 | 用途 |
|---|---|---|---|
| 拍网格 | beat / bar | `analysis.json`（BPM、第一拍、实测拍点） | 切点、脉冲、计数、灯光 |
| 歌词行 | line | `lyrics.lrc` 行时间 | 一句话的起止、窗口里的消息 |
| 词 | word | LRC 增强标签，或按音节权重估算 | 逐字显影、卡拉 OK、口型节奏 |

三层各有各的精度：

- **拍**决定"什么时候切"；
- **行**决定"这一段在说什么"；
- **词**决定"这个字什么时候亮"。

三者不能混用。常见错误是拿歌词行时间去切镜头——行与行之间往往隔着小节，
切点会落在半拍上，整片会有"拖一下"的观感。

### 时间的三档可信度

每个非网格时间都必须标注来源：

| 标记 | 含义 | 允许的用法 |
|---|---|---|
| `measured` | 音频分析测出来的强起音 | 直接使用 |
| `audit` | 对参考片逐帧审出来的 | 复现参考节奏时使用 |
| `initial` | 分镜初稿里写的"大概" | **必须**在验收前替换成 measured 或人工确认 |
| `ear` | 人耳最终确认 | 覆盖以上所有 |

`project.yaml` 里可以写 `{ line: 7 }` 或 `{ word: [7, 2] }`，编译器会解析成秒；
需要"这一行开始后半拍"就写 `{ line: 7, offset: 0.23 }`。**不要写裸秒数**，除非它本身就是网格上的事实。

## 3. 从歌到世界：先写世界圣经，再写分镜

一支 MV 不是"给每句歌词配一张图"，而是"一个世界在歌里发生变化"。
在写第一个镜头之前，先定四件事：

### 3.1 角色与色彩语义

参考片的做法值得迁移：**颜色不是装饰，是角色。**

- 橙 = "我"（被造出来的那一个）；
- 米白 = "你"（用户/人类/窗口另一边）；
- 红 = 错误/越界；
- 灰 = 缺席；
- 黑 = 系统/代码/终止。

一旦定了，整片不许违反。红色提前出现，观众会误读成"事故"；
橙色用在"你"身上，叙事关系就乱了。

### 3.2 三种画面（Plate 风格）

| 类型 | 是什么 | 什么时候用 |
|---|---|---|
| **界面** | 代码画出来的聊天窗口/设置页 | 对话发生、角色被"困"在窗口里 |
| **版画** | 整幅纸面印刷：剪影、图形、大字 | 歌词里的具体名词、情绪峰值 |
| **代码** | 纯黑底终端/清单 | 系统说话、循环、计数、宣判 |

三种画面轮换，才有"呼吸"。如果全片只有界面，就是屏幕录像；只有版画，就是幻灯片。

### 3.3 世界规则

写清楚"这个世界允许什么"：

- 窗口会不会被打破？角色能不能走出窗口？
- 剪影有没有脸？能不能被撕开？
- 文字是"界面的一部分"还是"印在纸上的字"？
- 什么时候允许套印错位（misregistration）？

规则越少越好，但一旦写下就不能临场改。Agent 最容易犯的错是"这一镜好看，破例一次"，
破例三次之后风格就没了。

### 3.4 叙事曲线

按段落列一张表：时间、段落、画面类型、调色板状态、情绪动作。
这张表是分镜的骨架，也是验收时的对照表。

## 4. 镜头语法

一个镜头（shot）由五个字段定义：

```yaml
- at: { bar: 6 }          # 何时开始（网格或行）
  until: { bar: 8 }       # 何时结束（可省略，默认到下一个镜头）
  scene: plate            # 用哪个场景函数
  moment: "她把'注意力'印成一张海报"   # 这一镜在叙事上做什么（一句话，必填）
  palette: warm           # 调色板状态
  enter: cut              # 入场方式
  lines: [3]              # 绑定哪几行歌词
  params: { word: ATTENTION, size: 300 }
```

### 4.1 `moment` 是硬约束

`moment` 不是备注，是验收标准。它必须回答"这一镜让故事往前走了哪一步"。
写不出 `moment` 的镜头，通常是"为了好看"的镜头，应该删掉或合并。

### 4.2 一镜一事

一个镜头只允许一个视觉主张：

- 要么"这个词变成画面"；
- 要么"窗口里的关系变了"；
- 要么"系统报错"。

同时做三件事的镜头，观众一件也记不住。

### 4.3 切点纪律

- 切点落在拍、半拍或小节线上；
- 入场方式只有少数几种（硬切、淡入、推、扫描、白闪），且必须与音乐事件对应；
- **不允许无动机的转场**：转场要么是"用户按了发送"，要么是"鼓点砸下来"，要么是"系统报错"。

### 4.4 层数

每一帧至少三层：

1. 背景（纸纹/网格/暗场，永远不是纯色）；
2. 主体（剪影/窗口/字）；
3. 前景或界面（扫描线、光标、标签、边框）。

只有两层的画面会"平"，三层以上才有印刷/屏幕的质感。

## 5. 视觉写作规则

### 5.1 三色印刷（Plate）

- 只允许三种油墨：主体色、纸色、黑；外加最多一个"点色"（如茄紫/番茄红）。
- 深度靠**第二色偏移**或**投影**，不靠渐变。
- 图形必须"第一眼可读"：轮廓清楚、大面积平涂、缩小到 480p 仍然认得出。
- 剪影不许有五官、不许动嘴；情绪靠姿态、错位、裁切、光照。

### 5.2 字体角色（两种风格通用）

| 角色 | 字体 | 用途 |
|---|---|---|
| 系统 | 等宽 | 代码、日志、计数、状态 |
| AI/角色 | 衬线 | 角色的"声音"、标题、大字 |
| 用户/界面 | 无衬线 | 按钮、设置、聊天气泡 |

字体角色一旦绑定，不许互换。参考片里"衬线 = 她，等宽 = 客户端，无衬线 = 你"，
观众不需要被告知就能感到谁在说话。

### 5.3 歌词可读性

- 歌词在**整个演唱时长内**可读；可以逐字显影，但不能提前消失。
- 关键字全大写 + 字号跳变 = 视觉峰值；一句里最多一个峰值。
- 版画底部的歌词带高度 ≥ 52 px（1080p），且压在暗带上，保证对比度。
- 卡拉 OK 的高亮**不能跑在声音前面**：`wordProgress` 必须以词的 `start` 为下限。

### 5.4 错位是情绪，不是 bug

套印错位（misregistration）、丢帧、撕裂只在**高潮段**出现，且有明确规则：

- 每一档错位至少持续 6 帧，否则看起来像渲染错误；
- 撕裂只发生在无脸剪影上；
- 错位量逐段增大（10 → 18 → 28 px），最后回到 0；
- 最后一个镜头必须是**干净、套准、静止**的，且是全片最亮的一帧。

## 6. 音频测量：不要相信"大概"

Agent 听不见音频，所以必须把"听感"变成数字。

### 6.1 节拍

本仓库的 `analyze` 做三件事：

1. 分帧计算低/中/高频带能量；
2. 用**正半波整流谱通量**得到起音强度（对鼓点、辅音都敏感）；
3. 对 60–190 BPM 的每个候选做**梳状滤波**：以该周期生成脉冲串，扫描所有相位，
   取"落在起音峰值上的平均强度"最高者；再用接近 120 BPM 的对数先验轻微加权，避免把八分音符当拍。

这比自相关稳，因为自相关容易锁到半拍/双拍。实测 98 BPM 的 demo 一次命中，置信度由"最佳得分 / 平均得分"的对比度给出。

### 6.2 拍点与强拍

- 从最佳相位生成拍点网格，再把每个拍点吸附到 ±70 ms 内最强的起音；
- 4/4 假设下，用低频能量选出"哪一拍是小节第一拍"；
- 输出 `beatTimes`，`Clock` 用分段线性插值，允许现场演奏的微小变速。

### 6.3 歌词

- 优先用增强 LRC（`<mm:ss.xx>` 词标签）；
- 只有行时间时，按音节权重把行窗口分给每个词（CJK 一字一拍，拉丁按元音组）；
- 行与行之间留 `gap`，最后一行用 `duration` 收尾；
- 任何"估算"的词时间都带 `estimated: true`，验收时优先人工确认。

### 6.4 为什么必须集中管理

把"大概时间"散落在场景代码里，是 MV 项目腐烂的开始。
本仓库要求：所有非网格时间出现在 `project.yaml` 的 `at/until` 或 `{line/word}` 引用里，
编译后落在 `plan.json`，并由 `STORYBOARD.md` 逐条列出。改时间只改一处。

## 7. 两种风格，同一台引擎

| 维度 | Plate | TUI |
|---|---|---|
| 空间 | 1920×1080 纸面 | 1280×720 桌面 |
| 基本单位 | 整幅版画 | 窗口/页面 |
| 颜色 | 暖黑纸 + 橙/米白/红 | 米白纸 + 蓝/墨/暗板 |
| 字体 | 衬线主体，等宽标签 | 等宽为主，聊天用无衬线 |
| 运动 | 套印错位、丢帧、光照棘轮 | 打字、窗口切换、图表生长 |
| 叙事 | 情绪版画，歌词名词外化 | 系统日志与对话并置 |
| 验收重点 | 三色纪律、剪影完整、字可读 | 网格对齐、层级、可读性 |

两者共享：时间模型、歌词模型、调色板状态机、场景注册、编译与渲染管线。
所以"换风格"不是重写，而是换一套 `scenes.ts` + 调色板 + 版式常量。

## 8. 失败模式清单

| 症状 | 根因 | 修复 |
|---|---|---|
| 整片像屏幕录像 | 所有镜头都用 `interface` | 按歌词名词排"版画债"：每个具体名词至少一次离开界面 |
| 切点"拖一下" | 用了歌词行时间而非拍网格 | 全部切点改 `bar/beat`，或吸附到半拍 |
| 画面很满但记不住 | 一镜多事 | 删到只剩一个主张 |
| 像 PPT | 没有层、没有纸纹、没有前景 | 补背景/主体/前景三层 |
| 红橙乱用 | 调色板语义失守 | 把颜色写进 world bible，验收时逐帧对 |
| 字被剪影吃掉 | 没有暗带/描边 | 底部暗带 + 字阴影，或把字放到纸上 |
| 高潮像渲染错误 | 错位持续 < 6 帧、撕裂有脸素材 | 遵守错位规则，只撕无脸剪影 |
| 换机器结果不同 | 用了系统字体/随机/时间 | 固定字体包、`frameRng`、禁用系统时间 |
| 音频对不上 | preroll / offset 处理错 | 用 `mv_start` 元数据与 `adelay` 核对首帧 |
| 全片没有一个干净镜头 | 一直在"坏" | 最后一个镜头必须干净、最亮、静止 ≥1.2 s |

## 9. 复现检查表

做完一支片，逐条打勾：

- [ ] 每个镜头都有 `moment`，且能在不看画面的情况下说清叙事作用；
- [ ] 所有切点都在拍/半拍/小节线上，误差 < 1 帧；
- [ ] 每个具体名词至少有一次"离开界面"的视觉化；
- [ ] 每帧至少三层；背景不是纯色；
- [ ] 调色板语义未被违反（红没有提前、橙没有给错人）；
- [ ] 歌词在整个演唱时长内可读，关键字有且只有一个峰值；
- [ ] 剪影无五官、无变形；错位/撕裂只在允许段落；
- [ ] 最后一个镜头干净、套准、静止 ≥1.2 s、全片最亮；
- [ ] 闪光预算：大面积亮度往返 ≤3 次/秒；
- [ ] 同一帧渲染两次哈希一致；
- [ ] `STORYBOARD.md` 的时间与 `plan.json` 一致，没有 `initial` 遗留；
- [ ] 成片首帧与歌曲第 0 秒对齐（`mv_start` 元数据核对）。

---

## 10. 一句话总结

**先把歌变成时间，再把时间变成语法，最后让语法生成画面。**
Agent 不需要"灵感"，它需要一套不会自我欺骗的约束。
