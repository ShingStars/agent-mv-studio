# 验收（QC）

> 验收不是"再看一遍"，而是一组**可重复的检查**：
> 每个检查都有命令、阈值、产物；失败时能定位到镜头与秒。

---

## 1. 验收门

| 门 | 时机 | 检查 | 产物 |
|---|---|---|---|
| G0 | 立项 | 授权、风格、交付规格 | `brief.md` |
| G1 | 测量后 | BPM/第一拍/拍点可信度 | `analysis.json` + 抽查截图 |
| G2 | 世界圣经后 | 色彩语义、角色规则 | `world.md` |
| G3 | 编译后 | 分镜完整、无空洞/重叠、moment 齐全 | `plan.json`、`STORYBOARD.md` |
| G4 | 资产后 | 透明、单色、无文字、可辨认 | 资产清单 |
| G5 | 静帧后 | 构图/可读/风格/切点 | 接触表、strip、评审 JSON |
| G6 | 成片后 | 同步、闪光、确定性、色彩 | `film.mp4`、QC 报告 |

任何一门失败，不进入下一门。

## 2. 自动检查

### 2.1 编译完整性

```bash
node dist/cli.js build <project>
```

阈值：0 error。warning 必须逐条解释（通常是 `errAt` 未设、镜头过短、引用了未测量的时间）。

### 2.2 确定性

```bash
node dist/cli.js check <project> --t 8.4
```

同一 `t` 渲染两次，比较 PNG 哈希。

- 通过：哈希一致；
- 失败：检查是否用了 `Math.random`、`Date.now`、系统字体回退、未固定的 `seed`。

> 浏览器抗锯齿在不同版本间可能有 1–2 个像素的差异；跨机器验收时记录浏览器版本，
> 不强求哈希一致，但要求**结构一致**（同镜头、同时间、同构图）。

### 2.3 闪光预算

```bash
node tools/qc.mjs flash <film.mp4>
```

实现：按帧取 160×90 灰度均值，检测相邻帧亮度差 > 0.12 的"跳变"，
统计每秒内的**上行+下行往返次数**。

阈值：

- 任意 1 秒内 ≤ 3 次往返；
- 全片最大单帧亮度差 ≤ 0.6（`flashStrength` 上限 0.5 时通常满足）；
- 若超限：降低切点密度、去掉白闪、把高对比图案的位移改为淡入。

输出示例：

```
frames 1002  ·  33.4s  ·  30fps
max round-trips/s: 2  (at 19.60s)
violations: 0
```

### 2.4 首帧对齐

```bash
ffprobe -v error -show_entries format_tags=comment -of default=nw=1 <film.mp4>
```

应输出 `comment=mv_start=-4`（或项目设定的 `-preroll`）。
再用播放器在 `t=0` 处暂停，确认第一拍与画面切点对齐（误差 ≤ 1 帧）。

### 2.5 时长

```
时长 = preroll + (end - start)
```

`ffprobe -show_entries format=duration` 应与之相差 < 0.05 s。

### 2.6 色彩

```bash
ffprobe -v error -show_entries stream=color_space,color_transfer,color_primaries -of default=nw=1 <film.mp4>
```

应为 `bt709 / bt709 / bt709`。若为 `unknown`，播放器可能按 BT.601 解释，颜色会偏。

## 3. 人工检查

### 3.1 接触表（每 2–4 秒一格）

```bash
node dist/cli.js sheet <project> --times 0,4,8,... --cols 4 --out out/sheet.png
```

逐格问：

1. 这一格属于这个世界吗？（颜色/字体/材质）
2. 三秒内能读懂它在做什么吗？
3. 字有没有被主体吃掉？
4. 和上一格相比，故事有没有往前走？

任何一格连续两次答"不"，就该重做。

### 3.2 切点 strip（15 帧）

```bash
node dist/cli.js strip <project> --t <切点> --out out/strip.png
```

看：

- 切点是否落在拍上（第 1 帧与第 15 帧之间的动作是否自然）；
- 是否有 1–2 帧的"空帧/闪白"；
- 运动方向是否连续。

### 3.3 全片播放（至少两遍）

第一遍看叙事：能不能复述"谁想要什么、发生了什么"。
第二遍看技术：闪烁、错位、字体回退、音频爆音、结尾是否干净。

## 4. 评审评分表（Vision Agent 用）

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 叙事 | 看不出在讲什么 | 有段落但缺弧线 | 可一句话复述且有转折 |
| 风格 | 像多个项目拼的 | 大部分统一，偶有跳脱 | 每一帧都属于同一个世界 |
| 时间 | 切点随意 | 大部分踩拍 | 切点与音乐事件互为因果 |
| 可读性 | 字/主体互相遮挡 | 需要暂停才能读 | 三秒内读懂 |
| 情绪 | 平 | 有一两个峰值 | 峰值有铺垫、有回落 |
| 技术 | 闪烁/边缘/压缩明显 | 小瑕疵 | 干净、稳定 |

发布建议：

- 总分 ≥ 24/30 且无单项 ≤ 2：可发布；
- 有单项 ≤ 2：修完再发；
- 叙事 ≤ 2：回到 G2/G3，不要修画面。

## 5. 常见技术缺陷与定位

| 现象 | 可能原因 | 定位方法 |
|---|---|---|
| 某段全黑 | 场景在 `t` 范围外返回空 | HUD 看 shot id；`still` 逐秒扫 |
| 闪白 | 转场 `whiteout` + 高亮背景 | 关掉该镜 `enter`，或降低 `flash` |
| 字体回退 | 字体未加载完成 | `doctor`；等待 `document.fonts.ready` |
| 剪影有白边 | 生图带白底/抗锯齿 | 退回重生成，不在引擎里修 |
| 颜色偏灰 | 播放器按 BT.601 | 确认 BT.709 tags |
| 音画差半拍 | `firstBeat` 错 / preroll 错 | 对齐 `mv_start` 与第一拍 |
| 渲染中断 | FFmpeg 退出，WS 仍在等帧 | 1 秒 probe；看 FFmpeg stderr |
| 结果每次不同 | 随机/时间/字体 | `check`；搜 `Math.random` |

```markdown
# QC — <project> — <date>

## 环境
- Node / FFmpeg / 浏览器版本：
- 字体：ok / missing
- 分辨率 / fps / 时长：

## 自动
- build：0 error / N warning
- determinism：pass / fail（t=…）
- flash：max N/s，violations N
- mv_start：-4（期望 -4）
- color：bt709
- duration：33.39s（期望 33.39s）

## 人工
- 接触表：<path>
- 逐镜头问题：
  | shot | 时间 | 问题 | 处理 |
- 全片复述：<一句话>

## 结论
- [ ] 可发布
- [ ] 修完再发（最小修复集：…）
```

## 7. 已知限制

1. **跨机器像素差异**：浏览器抗锯齿与字体栅格化可能不同；结构一致即可，不承诺逐像素哈希。
2. **节拍检测**：极端变速、自由节奏、强混响的曲子可能测错；必须人工抽查。
3. **歌词词时间**：纯 LRC 只能估算到音节级，不能替代强制对齐（forced alignment）。
4. **4K**：当前渲染按输出尺寸重绘，不放大；4K 需要更长的渲染时间与更大的显存。
5. **HDR**：输出为 SDR / BT.709；不做 HDR 管线。
6. **平台编码器**：默认 `libx264`；可用环境变量切换到硬件编码，但不同机器的码率/质量不同。
